# 本地 Markdown 待办应用 — 需求说明（PRD）

> 状态：可开发准备（待决已收口）  
> 更新日期：2026-11-23  
> 定位：Windows 本地应用；以 Markdown 为唯一数据源，供人与 AI 直接读写。

---

## 1. 一句话定位

一个极简本地待办工具：按日期拆分 Markdown 文件存储任务，用一份索引 MD 维护文件关系；无账号、无云端，AI 打开数据目录即可理解全部状态。

---

## 2. 已确认决策

| 项 | 结论 |
|----|------|
| 运行形态 | 本地 Windows 应用 |
| 数据载体 | Markdown 文件（不兼容 Obsidian 特殊语法） |
| 文件组织 | **按日期创建业务 MD** + **一份索引 MD** 记录文件关系 |
| 待处理视图 | 展示**全部**未完成事项 |
| 已处理视图 | 按**完成时间**筛选：本日 / 本周 / 全部 |
| 「本周」定义 | **周一 00:00 ～ 周日 23:59:59**（本地时区） |
| 截止日期 | **可选**（可空）；有字段与录入；**不做逾期判断/高亮/筛选** |
| 正文 | **必填**（文字或图片至少其一）；多行；支持粘贴/复制图片 |
| 列表展示 | 列表预览**只显示标题**（不显示正文） |
| 标题缺省 | 标题**非必填**；未填时用**正文纯文本前 8 个字**作为标题 |
| 删除策略 | **移入归档**（非物理删除）；操作前**二次确认** |
| 已处理项 | **可**打开编辑、归档、撤销完成 |
| 工作区 | **无默认目录**；首次启动必须选择文件夹；切换工作区 = 切换文件夹 |
| 数据刷新 | 提供**刷新**按钮，点击后重新从磁盘加载 |
| 归档列表 | **不重要**；第一版可不做独立入口 |
| 技术栈 | **Tauri 2 + TypeScript + React**；允许存在 `src-tauri`（Rust），业务与 UI 几乎全在 TS；本地能力优先用官方插件 |

## 3. 目标与非目标

### 3.1 目标

- 快速记录待办，并在列表中管理
- 待办正文支持多行说明，并可粘贴图片（落盘为本地文件 + MD 引用）
- 完成事项可按本日 / 本周 / 全部回看
- 全部状态落在可版本管理、可被 AI 直接阅读的 `.md` 中
- 删除可恢复（归档），避免误删丢数据

### 3.2 非目标（第一版不做）

- 账号、云同步、多端协作
- Obsidian / Tasks 插件语法兼容
- 看板、日历视图、优先级、标签、项目、子任务、重复规则
- **逾期**：过期高亮、逾期列表、逾期筛选、到期提醒（`due` 仅作展示与录入）
- **归档独立列表**（数据仍归档保留；无专门浏览入口也可）
- 系统通知 / 到期提醒（可后续迭代）
- 富文本排版（加粗/表格等）；正文以纯文本 + 图片为主
- 在 Rust 中实现业务逻辑（仅作壳与插件桥接）

## 4. 用户故事

1. **工作区**：首次启动必须选择一个文件夹作为工作区；之后可切换到其他文件夹（即切换工作区）。无工作区时不进入主界面业务操作。
2. **新增**：正文必填（文字或图片至少其一）；标题、截止日期可选。未填标题时用正文纯文本前 8 个字。保存后写入当前工作区。
3. **待处理列表**：列表预览**只显示标题**；点进编辑可看全文与图片。
4. **标记完成**：事项从待处理消失；写入 `completed`，进入「已处理」对应筛选。
5. **已处理**：本日 / 本周 / 全部；可打开编辑、归档、撤销完成。
6. **归档**：删除前弹出确认；确认后移入归档，离开常规列表，数据仍保留。
7. **刷新**：点击刷新后重新从当前工作区磁盘加载索引与日文件（用于外部改过 MD 后同步进应用）。
8. **图片**：正文中可粘贴 / 复制图片；落盘为本地附件 + MD 相对路径。
9. **AI 可读**：把工作区文件夹交给 AI，凭索引 + 日文件 + 附件即可还原任务。

## 5. 信息架构（界面）

```
┌─────────────────────────────────────────┐
│  工作区: D:\notes\todo    [切换] [刷新]    │
├─────────────────────────────────────────┤
│  [新增 / 编辑]                             │
│  标题（单行，可选；空则自动取正文前 8 字）      │
│  截止日期（可选，可空）                      │
│  正文（必填；多行；支持粘贴/复制图片）         │
├─────────────────────────────────────────┤
│  待处理 │ 已处理: 本日 | 本周 | 全部        │
├─────────────────────────────────────────┤
│  列表区（预览只显示标题，不显示正文）          │
│  - 标题                                   │
│  - 截止日期（有则展示；不做逾期处理）          │
│  - 创建/完成时间（按视图展示）                 │
│  - 操作：完成 / 撤销完成 / 编辑 / 归档(需确认) │
└─────────────────────────────────────────┘

首次启动（无工作区）:
┌─────────────────────────────────────────┐
│  请选择一个文件夹作为工作区才能开始使用        │
│           [选择文件夹]                    │
└─────────────────────────────────────────┘
```

### 5.0 工作区

- **工作区 = 一个本地文件夹**，即数据根目录（含 `index.md`、`days/`、`attachments/`）。
- **无默认路径**；不自动落到 Documents 等目录。
- **首次启动**：若尚未绑定工作区，必须先选择文件夹；选中后若目录为空则初始化结构，若已有本应用数据则直接加载。
- **切换工作区**：选择另一文件夹后，卸载当前数据视图，加载新文件夹内容（等同换库）。
- 应用可记住「上次打开的工作区路径」，下次启动直接进入；但用户仍可随时切换。记住路径 ≠ 默认数据目录。
- **刷新**：不切换文件夹，按当前工作区路径重新读盘加载。

### 5.1 列表字段展示建议

| 视图 | 展示字段 |
|------|----------|
| 待处理 | **标题**、截止日期（可空）、创建日期；**不展示正文** |
| 已处理 | **标题**、完成时间、原截止日期（可空）；**不展示正文** |

### 5.1.1 标题生成规则

- 用户填写了标题 → 列表与存储均使用该标题。
- 用户未填标题（空或仅空白）→ 保存时从 **body 纯文本** 取前 **8 个字** 写入 `title`：
  - 忽略图片语法（如 `![](...)`）及多余空白/换行后再截取；
  - 「字」按 Unicode 字符计（中文 1 字 = 1 字符）；
  - 正文纯文本不足 8 字 → 有多少用多少；
  - 正文也无可用文字（例如只有图片）→ 标题记为 `未命名`。
- 之后用户若手动改标题，以用户输入为准；不因正文变更自动覆盖已有非空标题（避免列表标题被悄悄改掉）。若产品上要「标题跟随正文」，留作二期。

排序建议（可配置项留后续）：

- 待处理：默认按截止日期升序，**无截止日期靠后**；同日按创建时间
- 已处理：默认按完成时间倒序

### 5.2 正文与图片交互

- 正文为多行文本编辑区；允许换行；**保存时必填**（纯文本非空，或已插入至少一张图片）。
- 标题与正文皆空、且无图片 → 禁止保存并提示。
- **粘贴图片**：剪贴板含图片时（如截图），粘贴写入附件目录，并在光标处插入 MD 图片语法。
- **复制图片**：选中正文中的图片后复制，可将图片放入剪贴板供外部粘贴。
- 第一版不要求完整所见即所得；至少保证：编辑时可预览已插入图片，保存后重新打开仍可见。

### 5.3 归档确认与已处理操作

- 归档（删除）前弹出确认对话框，用户确认后才执行。
- 已处理列表中的事项：**可编辑**（标题 / due / 正文 / 图片）、**可归档**（同样需确认）、**可撤销完成**。

## 6. 数据模型与 Markdown 约定

### 6.1 目录结构

```
{数据根目录}/
  index.md                 # 索引：所有任务与文件关系
  days/
    2026-11-23.md          # 按「任务归属日期」的日文件（见 6.2）
    2026-11-24.md
  attachments/
    task-20261123-001/
      img-001.png          # 该任务粘贴的图片
      img-002.webp
```

> 第一版推荐：**任务正文始终写在创建当日的 `days/YYYY-MM-DD.md`**；归档只改状态 + 索引，不立刻搬文件与附件，避免路径抖动。

### 6.2 「按日期创建 MD」的归属规则

- **创建时**：以**创建日（本地）**决定写入哪个 `days/YYYY-MM-DD.md`。
- **完成 / 归档**：默认**不改文件归属**，只更新条目字段与 `index.md`。
- 索引负责跨文件查询：「全部待处理」「按完成日筛选」等。

### 6.3 单条任务 Schema（应用自定义，非 Obsidian）

日文件中每条任务使用统一块格式，例如：

```markdown
# task-20261123-001

- status: pending
- title: 提交周报
- due: 2026-11-24
- created: 2026-11-23T09:15:00
- completed:
- archived: false
- updated: 2026-11-23T09:15:00

### body

## 周报要点

1. 完成登录修复
2. 见截图

![截图](../attachments/task-20261123-001/img-001.png)
```

> 任务块用 `# task-id`（H1）；正文内标题从 `##` 起。日文件顶部日期行亦可为 `# YYYY-MM-DD`。读取时仍兼容旧的 `## task-id`。

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 全局唯一，如 `task-YYYYMMDD-序号` |
| status | enum | `pending` \| `done` \| `archived` |
| title | string | 标题，**单行**；可空输入，保存时按 [5.1.1](#511-标题生成规则) 补全 |
| due | date \| empty | 截止日期 `YYYY-MM-DD`；**可空（非必填）** |
| created | datetime | ISO 本地或带偏移时间 |
| completed | datetime \| empty | 完成时间；仅 `done` 有值 |
| archived | bool | 是否归档；归档时 `status=archived` |
| updated | datetime | 最后修改时间 |
| body | markdown | **多行正文，必填**；可含标准图片语法 `![](...)` |

**正文必填（已确认）：**

- 保存时：正文纯文本非空，**或**至少一张图片引用；否则拒绝保存。

**截止日期策略（已确认）：**

- UI 提供日期选择；**允许留空**（无截止日期）。
- 无强制必填开关。

**图片存储约定：**

- 物理文件：`attachments/{task-id}/img-NNN.ext`（`png` / `jpg` / `webp` 等常见格式）。
- MD 引用：相对日文件的路径，如 `../attachments/task-xxx/img-001.png`。
- 粘贴时由应用生成文件名并写入；删除正文中的图片引用后，附件是否立即物理删除可二期再定（第一版可保留孤儿文件，或保存时做简单清理）。
- 索引**不**展开图片列表；需要时从 body / 附件目录读取。

### 6.4 索引文件 `index.md`

索引是「文件关系与快速扫描」的权威目录，建议结构：

```markdown
# Todo Index

> 由应用维护。勿手改 id / path；手改 status 后需在应用内刷新。

## Files

| path | date | task_count |
|------|------|------------|
| days/2026-11-23.md | 2026-11-23 | 3 |
| days/2026-11-24.md | 2026-11-24 | 1 |

## Tasks

| id | status | title | due | created | completed | archived | file |
|----|--------|-------|-----|---------|-----------|----------|------|
| task-20261123-001 | pending | 提交周报 | 2026-11-24 | 2026-11-23T09:15:00 |  | false | days/2026-11-23.md |
| task-20261122-004 | done | 修登录 |  | 2026-11-22T11:00:00 | 2026-11-23T10:02:00 | false | days/2026-11-22.md |
| task-20261120-002 | archived | 废弃需求 | 2026-11-21 | 2026-11-20T08:00:00 |  | true | days/2026-11-20.md |
```

> 索引表可不含 body 全文（避免巨大表格）；详情以日文件为准。`due` 列允许为空。

约定：

- **日文件**是任务正文的 source of truth。
- **索引**与日文件保持同步；应用每次写操作后更新索引。
- AI / 外部工具：优先读 `index.md` 做总览，再按 `file` 打开详情。
- 若索引与日文件不一致：以日文件为准，提供「重建索引」能力（设置项）。

### 6.5 状态机

```
        新建
          │
          ▼
      pending ──归档──► archived
          │                 ▲
          │ 完成            │
          ▼                 │
         done ──归档────────┘
          │
          │ 撤销完成
          ▼
      pending
```

- **归档**：须用户确认；从待处理 / 已处理常规列表移除；数据保留。待处理与已处理均可归档。
- **撤销完成**：仅 `done → pending`，清空 `completed`；已处理列表提供此操作。
- **从归档恢复**（建议二期；第一版可不做 UI，数据仍保留）。

## 7. 视图与筛选规则

| 视图 | 条件 |
|------|------|
| 待处理 | `status = pending` 且 `archived = false`（全部未处理） |
| 已处理 · 本日 | `status = done` 且 `completed` 的本地日期 = 今天 |
| 已处理 · 本周 | `status = done` 且 `completed` ∈ [本周一 00:00, 本周日 23:59:59] |
| 已处理 · 全部 | `status = done` 且未归档 |
| 归档 | 数据保留；**第一版不做独立列表入口** |

时区：一律使用**系统本地时区**解释「今天 / 本周」。

## 11. 验收标准（摘要）

1. 无工作区首次启动 → 必须选文件夹后才能使用；空目录会初始化结构。
2. 切换工作区 → 列表内容变为新文件夹数据。
3. 外部改 MD 后点刷新 → 应用内列表与磁盘一致。
4. 正文为空且无图时无法保存；有正文或有图可保存。
5. 不填标题、正文为「今天要提交周报草稿」→ 标题为「今天要提交周报」；列表不出现正文全文。
6. 不填标题且正文仅有图片 → 标题为「未命名」。
7. 粘贴图片 → 附件落盘 + MD 引用；可复制到外部应用。
8. 完成 1 条 → 「本日已处理」可见；已处理项可编辑、可撤销完成、可归档。
9. 归档前出现确认；确认后常规列表不可见，磁盘数据仍在。
10. 「本周已处理」仅含本周一至周日完成的事项。
11. 仅保留工作区文件夹时，AI/人可读 `index.md` + 日文件 + 附件还原任务。
12. 损坏索引后「重建索引」与日文件一致。

## 12. 已收口决策 / 剩余待决

### 已确认

1. 截止日期：**非必填**，可空。
2. 归档独立列表：**不重要**，第一版不做。
3. 正文：**必填**（文字或图片至少其一）；多行；支持粘贴/复制图片。
4. 列表预览：**只显示标题**，不显示正文。
5. 标题：**非必填**；空则取正文纯文本前 **8** 字；无可取文字则为「未命名」。
6. 归档：**二次确认**。
7. 已处理：**可编辑、可归档、可撤销完成**。
8. 工作区：**无默认目录**；首次必选文件夹；切换工作区 = 切换文件夹；可记住上次路径。
9. 刷新：**手动刷新**重新加载；不做自动文件监视。

### 仍可随实现再定

1. 安装形态：优先 **便携 / 单目录运行**；需要时再补安装包。
